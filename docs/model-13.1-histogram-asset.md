# Model 13.1 Histogram Asset

## Name and provenance

`model131-discard-histograms.bin` is the **Model 13.1 histogram asset**.
Model 9.1 is its rollout-policy provenance, not the asset's model identity:
the outcomes were generated by the original context-free, observation-only
pegging policy used by Model 9.1 when the asset was built, while Model 13.1 is
the model that consumes the full joint distributions for board-aware discard
decisions. Model 9.1 itself uses only the compact mean-EV table. Its live
policy was later corrected to include actor-owned discards and the cut; that
does not rewrite this frozen asset.

The original six-byte-bin compiler output has magic `M91HS001` because it was
emitted during the Model 9.1 rollout build. The packaged runtime representation
is the lossless `M131H001` file. Every decoded row and bin was checked against
the original output; no probability was rounded or quantized.

## Comparison with Model 13.0

| Property | Model 13.0 pairwise file | Model 13.1 histogram asset |
| --- | --- | --- |
| Runtime path | `model13-pairwise.bin` | `model131-discard-histograms.bin` |
| Format | `P12P` version 1 | `M131H001` version 1 |
| Size | 55,905,748 bytes (53.316 MiB) | 99,869,610 bytes (95.243 MiB) |
| Stored rows | 3,274,375 dealer and 10,676,575 pone/lead opponent-keep records | 330,590 six-card/discard/role histogram rows |
| Stored outcomes | One result for a specified own keep, opponent keep, role, and pone lead | 24,884,749 occupied `(own points, opponent points)` bins with exact weights |
| Runtime work | Scan and reweight every compatible opponent keep for each discard candidate | Direct row lookup; opponent-keep weighting was pre-aggregated after removing all six visible cards |
| Pone leads | Separate record ranges allow discard-time comparison of forecast leads; the executable lead is recomputed after the cut | The stored distribution reflects its observation-only rollout policy; no unused Model 13.0 pre-cut lead scan is performed, and the executable lead is recomputed after the cut |
| Offline policy information | Both four-card keeps were available to the solver; this permits strategy fusion | Each action received only that actor's cards and public pegging history |
| Live pegging | Model 13.0's frozen pegging evaluator | Model 13.0's same frozen pegging evaluator |
| Cut and crib conditioning | Not represented in the reusable pairwise outcomes | Not represented in the reusable histograms |

The Model 13.1 file is 1.786 times the size of the Model 13.0 file, or 78.64%
larger. It is larger because the compatible-opponent aggregation is repeated
and stored for every visible six-card/discard context. In exchange, runtime no
longer scans thousands of opponent-keep records to construct a pegging
distribution.

Model 13.0's file preserves more intermediate structure: it can reweight a
specific opponent keep and compare alternate pone leads at runtime. Model
13.1 deliberately collapses that structure into the exact distribution the
legal asset-building policy produces in each discard context. It therefore fixes
the strategy-fusion problem, but cannot later substitute a different pegging
policy or recover opponent-keep correlations without rebuilding the asset.

## Model behavior

Model 13.1 retains Model 13.0's hand scoring, crib distributions, board model,
win-probability discard objective, EV tie-break, post-cut live lead selection,
and live pegging. Only the discard-time pegging distribution is replaced by
the legal Model 13.1 histogram. Consequently, the corrected Model
13.0-versus-13.1 benchmark is a discard-asset-only ablation.

Model 13.0's pairwise discard forecast still selects a pre-cut lead because
that selected lead determines which pairwise histogram evaluates its discard.
Model 13.1's stored histogram already fixes its asset-building rollout policy,
so a separate Model 13.0 pre-cut lead scan cannot affect its discard objective
and is not performed. For both models, after the cut is revealed, the shared
Model 13 live evaluator computes the executable pone lead using the actor's own
discards, the cut, and public cards. Opponent discards remain hidden.

This creates a deliberate policy mismatch: the replacement histogram was
rolled out with the original context-free Model 9.1 policy, whereas executable
live cards, including the post-cut opening lead, come from Model 13.0. That is
the controlled experiment requested here; it measures the value of substituting
this discard forecast without also changing how games are actually pegged.

The legal policy still has known quality limitations. It averages legal future
continuations rather than solving an optimal information-set strategy, omits
the cut and actor-owned crib cards so the keep-pair outcomes remain reusable,
and begins from the specified compatible-hand prior. “Leakage-free” means its
actions never depend on hidden opponent cards; it does not mean the policy is
optimal.

## Superseded mixed-policy benchmark

The first 10,000-game benchmark completed on 2026-08-27, but it changed both
the discard asset and live pegging. It is retained for provenance and must not
be interpreted as the discard-only comparison. Model 13.1 scored 4,518 wins
to Model 13.0's 5,482 (45.18%, Wilson 95% interval 44.21%–46.16%) and averaged
1.8912 fewer points per game. Its much faster live-pegging timing also exposes
the policy change directly: 1.268 ms per decision versus Model 13.0's 31.971
ms. Total wall time was 91 minutes 27 seconds.

Its fixed contract was:

- 5,000 games with Model 13.1 on the left and Model 13.0 on the right;
- 5,000 games with the model sides reversed;
- the same deterministic seed sequence, beginning at `0x13101301`, in both
  orientations;
- alternating first deal within each orientation;
- four workers per orientation, with both orientations running concurrently;
- per-game SQLite records, per-decision timing, live status/ETA, and a final
  combined report with a 95% Wilson interval and paired-seed outcomes.

The durable output root is:

`benchmarks/model131/evaluation-20260827/13.0-vs-13.1-10k/`

The final result is `paired-summary.json` under that root.

## Superseded pre-cut-lead discard-only partial run

The first discard-only rerun used identical Model 13 live pegging on both
sides, but its runner still executed the lead selected before the cut. It was
stopped on 2026-08-28 after preserving 942 games in the 13.0-left orientation
and 938 games in the 13.1-left orientation. Its durable root is:

`benchmarks/model131/evaluation-20260828/13.0-vs-13.1-discard-only-10k/`

These 1,880 games are provenance only and must not be mixed with the corrected
run.

## Corrected discard-only benchmark

The corrected 10,000-game run keeps Model 13.0's lead selection and live
pegging on both sides. Its only model difference is the discard-time pegging
distribution. It uses the same two-orientation, paired-seed, alternating-first-
deal, four-workers-per-orientation contract described above. Its durable root
is:

`benchmarks/model131/evaluation-20260828/13.0-vs-13.1-discard-only-legal-leads-10k/`

The two live status files are `13.1-left/status.json` and
`13.0-left/status.json`. On completion, the launcher writes
`paired-summary.json`. The resumable launcher and reporter are
`scripts/run-model131-10k.sh` and `scripts/report-model131-benchmark.cjs`.

On 2026-08-28 the run was resumed with an optimized runner after 868 complete
13.1-left games and 908 complete 13.0-left games. Five interrupted tail
indexes in each orientation were completed first, leaving both databases as
contiguous zero-based prefixes with no completed-game loss. The optimized
runner removes Model 13.1's unused Model 13.0 pre-cut pairwise lead scan. A
same-seed differential smoke test confirmed identical games, discard records,
and pegging records before and after the optimization. Both runner hashes and
the parity seed are recorded in the benchmark manifest.
