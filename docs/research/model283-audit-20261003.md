# Model 28.3: information, strategy and performance audit

Later corrections: [compact root counting and reuse](model283-compact-counting-20261003.md)
repairs the root correlation issue; [future rank counting and the renewed 20.x
audit](model283-future-counting-20261004.md) replaces board-only future valuation
without expanding private hand contexts. The findings below describe the
original snapshot, not an assertion that all omissions remain present.

2026-10-03. Audited the uncommitted native 28.3 implementation on
`work/model283-score-blocks`, based on `e8098cc828793bcc1faf46fae3eb113f3124a13c`.
All 199 frozen source/build/asset inputs still match the completed integration
test. This assessment changes no playing code, assets or build configuration.

## Conclusions

- No hidden-card leak or strategy-fusion shortcut was found in the current
  decision path. The implementation chooses once per acting hand and public
  history, across the actor's weighted opposing possibilities.
- This is still a strategically simplified model. Future private discards are
  omitted; future decisions use board-only WP; live counting valuation retains
  the baseline's marginal-distribution approximation. Registering the model did
  not remove these approximations.
- The representation saves memory, but it is not a computation over only the
  few thousand distinct scoring sequences from the earliest experiments. It
  resolves many public rank branches and hand-pair outcomes before aggregating
  terminal scores.
- PGO was deliberately bypassed for initial integration/feasibility. The
  optimized comparison is unfinished. The measured 3.27x pone-opening ratio is
  for the ordinary release builds and must not be advertised as a PGO result.
- Three matched deals establish integration and limited feasibility, not a
  playing-strength result or nonregression guarantee.

## Why the integration test omitted PGO

The validation stage explicitly called `build_rust_release.py benchmark
--no-pgo`. This was a choice to complete the first native integration check
without the additional baseline/instrumented/profile-use build-and-replay
cycle, not a technical restriction of 28.3. Both compared models used the same
ordinary release build and all measured CPU was on efficiency cores. The
comparison is useful for that build, but incomplete for normal optimized use.

Mac PGO remains automatic in the normal build script. Its benchmark training
default is **20.7**, however. A 28.3 comparison should explicitly supply both
`--model schell_table-peg_table-28.3` and
`--model schell_table-peg_table-20.7`. Merely building 28.3 code with a profile
trained only on 20.7 is not an adequate assessment of this new solver. The
existing build pipeline verifies exact choices and value bits on training and
held-out inputs before publishing the optimized binaries.

Prior compiler experiments found useful PGO gains on older models; their
percentages cannot be transferred to 28.3. A fresh trained comparison is needed.
No PGO build or additional long benchmark was started by this audit.

Source: `scripts/build_rust_release.py:120,139,178-201`.

## Information audit

| Check | Finding and evidence |
|---|---|
| Actual hidden cards reaching the live decision | `decision.rs:320-351` passes own keep/discards, public cards/history, scores, count and opponent card count. It does not pass the opponent's remaining cards or private discards, or the complete crib. The generic input also contains an RNG-derived seed, but the 28.3 path does not use it. |
| Opponent forecasting with A's actual hand fixed | Avoided. `model283.rs:586-657` builds both domains from public evidence. At a candidate lead, `702-722` retains all own holds that could legally make that lead, not only A's actual hold. A's actual row is selected for root valuation only afterward. |
| Choice differing by hidden opponent hand | Avoided in contested decisions. `462-515` computes a weighted histogram over all opposing holds, selects one branch for the acting hold, and then copies that same selected branch across all its opposing columns. |
| Clairvoyant C operations | Compatibility checks and physical scoring may inspect a hypothetical pair. Pair-specific action optimization is limited to a publicly empty opponent; when both have at most one card, remaining actions are forced. Those cases have no unresolved hidden-dependent choice by the other player. See `375-424,547-568`. |
| Private discard leakage | Actual root discards affect only the root posterior and counting valuation. Public hypothetical domains are not narrowed by those private discards. Future policies omit private discard information rather than receiving the other player's actual discards. This is a strategic approximation, not extra information. |
| Persistent action/cache contamination | The score-block solver is created per forecast and has no production action book or continuation memo. The recorded action book exists only in tests. Immutable assets are shared. |

New end-to-end check: **10 nonforced late positions, 80 legal hidden-state
substitutions**, covering both roles and both physical seat orientations. Each
substitution changes the other player's remaining physical cards, private
discards, complete crib and game RNG state while preserving the actor's legal
information. Historical plays and Go declarations are replayed through the
native rules; 102 impossible sampled substitutions were rejected. Every accepted
substitution preserves the exact chosen physical card and EV/WP bits, including
calls through shared hand-cache objects.

Existing passed checks also include the hidden-4/7 witness (one shared action,
75% expected WP rather than clairvoyant 100%), a bounded independent backward
reference covering more than 2,000 recorded information-group choices per
representation, and compact/native physical-transition agreement.

One validation claim needs narrowing: despite its name, the frozen full-deck
opening test at `model283_tests.rs:255-283` checks the winning rank and its
expected board WP (within 1e-12). It does **not** compare every candidate's
entire outcome distribution against the standalone run. The bounded reference
does compare endpoints and group choices, but full-deck distribution parity is
not established by that opening test. Earlier descriptions of it as full
distribution parity were too broad.

This is strong evidence for the inspected implementation, not an exhaustive
proof over all possible games. In particular, the new substitutions cover late
positions; the opening information separation is established by the source
trace and prior tests, not 80 new opening solves.

## Strategic simplifications and possible weaknesses

| Priority | Simplification | Consequence and possible improvement |
|---|---|---|
| High | **Future actors forget their own private discards.** `Hand` contains initial/remaining keep ranks only; inner depletion at `model283.rs:325-334` subtracts the keep, public cards and cut. | The real actor has this information. Even the current root player's future self is forecast without it. A later live decision can revise its choice, and the root can rely on a continuation it will not actually follow. This is less information than 20.7's rollout state, which carries both actors' own discard context (`model1323.rs:956-966`). Restoring legal discard conditioning is a strength experiment; avoid simply exposing A's actual discards to B. |
| High | **Future decisions use generic after-pegging board WP.** `model283.rs:251-262`; live selection uses `model.rs:2206-2229,6013-6062`. | The future actor does not use its known counting hand or private crib contribution to choose a move. A pone already holding enough counting points to win should value survival differently from an average hand. The root's full evaluator cannot undo a poor future choice after alternatives have collapsed. Board-only inner valuation also exists in the 20.7 policy (`model91_compact.rs:399-417`); 28.3 retains this mismatch. Aligning future and live valuation is worth a separate strength/cost test. |
| High | **Root pegging and counting/crib outcomes are not jointly conditioned.** `model283.rs:723-747` merges hand-specific outcomes into score pairs. `model.rs:6027-6062,6331-6415` applies separately prepared hand and crib marginals. | A pegging result can correlate with the opponent hold, which correlates with counting and crib outcomes. Those correlations are lost before the live WP calculation. Near scoreouts this can misprice risk. This is inherited from 20.7, so matching its valuation bits does not establish exact full-hand WP. Retaining a hand-conditioned terminal valuation could use information already present in the score blocks. It need not expose that hand to a player's choice. |
| Medium | **Future private contexts are rank-only.** | This is exact for pegging arithmetic, but not for the full private information needed by a future counting-aware policy: suits affect flushes/nobs and private discards affect beliefs/cribs. Actual live root counting still uses physical cards. Any future full-WP upgrade must handle this deliberately. |
| Medium | **Belief updates use fixed empirical decline factors, not the newly selected policy's action likelihood.** `model283.rs:268-305`, `model132.rs:1258-1332`. | Legal card/Go exclusions remain enforced, but soft evidence can differ from how 28.3 itself plays. This can produce inconsistent predictions or undervalue information revealed by a move. It is not a solved equilibrium or a guarantee that both actors make globally optimal choices under one self-consistent probability model. Revising this is model research, not an exact speed optimization. |
| Medium | **Discard and long-range assets remain those of the baseline.** `model.rs:1933-1948,2062-2080`, `model1323.rs:375-423`. | Discards use the retained correction histogram, and board/hold/decline assets were not rebuilt for 28.3. A keep good under the older pegging policy need not be best under the new one. Preserving these isolates the pegging experiment, but leaves adaptation/calibration work if 28.3 proves worthwhile. |

No low-probability hand sampling, time cutoff, fallback to 20.7 future actions or
deliberately shallow pegging horizon was found in 28.3. The omissions above are
about information and valuation, not an early stop in the legal card tree.
Deterministic best-action choice follows the requested design; mixed/equilibrium
strategy strength has not been established.

These are credible mechanisms for errors, not measured win-rate losses. Their
repairs could improve or harm real playing strength and may cost time. They must
be evaluated separately from optimizations expected to preserve exact behavior.

## Performance work still available

The main structural cost is at `model283.rs:416-525`: every legal public rank
branch is solved, then each own hold scans opposing holds to form weighted
terminal histograms. Compact score cells reduce retained storage. A constant
table is usually detected only after its cells have already been calculated.

The earlier standalone version of this same four-card-hold core recorded
959,955–1,808,016 score blocks and 3,510,820–6,000,982 choice groups over its three
complete hands. Those are **earlier standalone counters**, not fresh native
profiling measurements. They corroborate the source finding that this is not
just a sweep over the original few thousand distinct scoring sequences. There
is no demonstrated lower bound proving all this work necessary.

| Priority | Opportunity | Assessment and guardrail |
|---|---|---|
| First measurement | Fresh PGO for both compared models | Restore the normal compilation standard and verify exact results. Benefit for 28.3 remains unmeasured. |
| High | Reuse posterior components with indexed hand rows | `weights()` rebuilds a hash map and reconstructs relative history per block. `weight()` repacks the opposing hand and recomputes combinatorial denominators over 13 ranks per pair. Cache/read immutable raw rows by role and observed ranks; precompute denominators and hand IDs; reuse weights for actions at the same legal context. Preserve actor-private conditioning and floating-point operation order. |
| High | Skip valuation for forced rows | Even an own hold with one branch gets a weight vector, histogram and WP sum. Once support is established, its sole legal branch can be copied without comparing utilities. A whole public block may still contain choices for other holds, so do this per row where justified. |
| High | Direct score indexing and reusable scratch | A new `BTreeMap<u16,f64>` is allocated for every own-hold/action histogram. The score-pair domain is bounded. A reusable array plus touched indices can replace tree allocations, preserving the current sorted-bin summation and within-bin accumulation order. Reuse member, weight and result buffers too. |
| High | Fixed storage and incremental public evidence | `Position::after` clones history/series vectors; each block converts history again and recomputes likelihoods. The series has at most eight cards, and both perspectives can be maintained incrementally with exact integer likelihood operations. Verify Go/reset behavior and the soft-support floor. |
| Potentially high, proof needed | Share physical scoring/forced suffixes across belief contexts | Current suffix scoring repacks both remaining hands and recomputes transitions for every compatible pair, with no memo. C may reuse equivalent physical states while retaining separate beliefs and decisions. Cache keys must preserve count, series, turn/Go/last, remaining ranks and scoreout behavior. Never share policy decisions solely because physical scores currently match. |
| Potentially high, proof needed | Exact pruning and earlier equivalence reduction | 28.3 does not call 20.6's ordered-root/direct-bound pruning. C can compute pair-specific reachable-score bounds, then aggregate them over the actor's legal weighted information group before eliminating an action. Bounds must include ties and floating-point safety. Combining branches merely because their current score or immediate points match is unsafe. |
| Medium/structural | Process fewer irrelevant cells and merge equivalent subproblems | Tables are dense over each current hand-domain product, including incompatible cells. Sparse indexing or common result vectors can reduce work/storage where measured. Merge histories only when future legal actions, beliefs, relevant private information and utilities are equivalent. Current terminal compression alone does not do this. |
| Lower expected impact | Remove inherited setup that 28.3 does not use | Root preparation creates the older policy object to obtain a posterior and sets continuation flags that the independent score-block solver never consults. A smaller posterior-only preparation interface can avoid unused setup. Do not mistake it for the main millions-of-groups cost. |
| Latency option | Parallel independent root candidates when spare cores exist | Could reduce wall time while increasing concurrent memory and leaving total CPU work broadly unchanged. Preserve canonical final comparison/tie order. The existing one-worker runs intentionally did not claim multi-core latency. |

There is also no persistent expected-line book: later live decisions recompute.
The measured mean extra pone time after its opening was only about 0.66 wall
seconds, so avoiding those later calls cannot explain or recover most of the
134.60-second opening. Reuse **within** the opening deserves priority. A blind
replay of its predicted future moves would be incorrect while the live/future
information and valuation mismatches above remain. The project ADR also excludes
a persistent observation-to-action table.

The hand harness requests full recommendations/values. The normal choice-only
entry point already skips valuation for forced ranks. This distinction can
affect later-move totals, but none of the three measured pone openings was a
forced-rank choice.

These speed opportunities are code-supported candidates, not measured gains.
First establish the fresh-PGO baseline, then test one change at a time against
unchanged actions, distributions/value bits and the existing legal-information
reference. Strength/valuation changes need separate playing tests.
